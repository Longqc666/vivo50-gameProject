# 交互与谜题接口说明（成员4 → 全员）

> 版本 V1.0 · 2026-11-15 · 定义与维护：庞华杰（成员4，团队负责人）
> 对应策划案：[策划案.md](策划案.md) 5.2 探索/提示、5.4 躲藏与失败重试、5.5 道具与主线谜题链
> 对应分工：[分工表.md](分工表.md) 4-1 交互契约、4-2 拾取与背包、4-3 条件交互、4-4 谜题链、4-5 躲藏点
>

> 本文是接口契约，不是完成记录；实际行为以代码与 `Assets/Tests/Interact` 的自动化用例为准。

## 1. 一句话

交互物只回答三件事：**现在是什么状态、提示写什么、按下 E 之后发生什么**；
按键、距离、提示显示、任务判定分别由成员1、成员5、成员6 负责，两边不重复实现。

## 2. 契约 `IInteractable`

```csharp
public interface IInteractable
{
    string DisplayName { get; }                                  // 提示与日志用的名字
    Transform Anchor { get; }                                    // 交互锚点，调用方算距离
    bool IsActive { get; }                                       // 是否还参与检测（拾取后 false）
    InteractionState EvaluateState(InteractionContext context);  // 四态判定，只读、无副作用
    string GetPrompt(InteractionContext context);                // 提示或不可用原因
    InteractionResult Interact(InteractionContext context);      // 执行一次
}
```

`InteractionContext` 携带本次交互的上下文，成员1 直接调用 `InteractionContext.For(player)` 即可：

| 字段 | 类型 | 说明 |
|---|---|---|
| `Actor` | `GameObject` | 发起交互的角色；躲藏点、背包都从它身上找 |
| `Inventory` | `Inventory` | 角色背包；为空时拾取/谜题会返回「背包未初始化」而不是崩溃 |
| `Quest` | `IQuestLog` | 任务进度来源；场景无提供者时退回临时日志并打印一次警告 |

`InteractionResult`：

| 成员 | 说明 |
|---|---|
| `Succeeded` | 是否成功 |
| `Message` | 给玩家的反馈文本（成功说明或失败原因），成功后可直接当字幕显示 |
| `InteractionResult.Ok(text)` / `Rejected(reason)` / `Ignored` | 构造方式，`Ignored` 表示本帧静默忽略 |

## 3. 四态与提示格式

| 状态 | 含义 | 标准提示 | 调用方行为 |
|---|---|---|---|
| `Pickupable` | 可拾取 | `[E] 拾取 手电筒` | 允许按 E |
| `Inspectable` | 可调查 | `[E] 查看 宿舍便笺` | 允许按 E |
| `Usable` | 可使用 | `[E] 使用 配电箱` | 允许按 E |
| `Unavailable` | 暂不可用 | 只显示原因，例如 `配电箱缺少「保险丝」：先去设备间把它找出来。` | 仍显示提示，但按 E 只回原因 |

- 提示统一由 `InteractionPrompt.For(state, name)` / `InteractionPrompt.Action(verb, name)` 生成，键位显示集中在 `InteractionPrompt.KeyLabel`（默认 `E`）。
- 特殊动词例外：躲藏点用 `[E] 躲进 储物柜` / `[E] 离开 储物柜`（策划案 4 操作表里「藏入/离开柜子」）。
- **不可用时必须给原因**（T03/T07/T08 的验收点），不能只显示对象名。

## 5. 调用示例（成员1 的 `PlayerInteractor`）

```csharp
// 示意代码：成员1 在自己的 PlayerInteractor 中这样接入，无需修改交互物。
[SerializeField] private float interactRadius = 1.2f;   // 策划案 9 数值表

private void Update()
{
    if (GameState.Current != GameState.Explore) return;  // 暂停/失败时由成员6 冻结

    IInteractable nearest = FindNearest(interactRadius); // 遍历场景内 IsActive 的交互物
    InteractionContext context = InteractionContext.For(gameObject);

    hud.SetPrompt(nearest != null ? nearest.GetPrompt(context) : string.Empty);

    if (Input.GetKeyDown(KeyCode.E) && nearest != null)
    {
        InteractionResult result = nearest.Interact(context);
        if (result.HasMessage) hud.ShowFeedback(result.Message); // 成功/失败都显示
    }
}
```

注意事项：

- `InteractionContext.For` 每次会 `GetComponentInParent<Inventory>` 并解析任务进度；建议在 `Start` 缓存一次，场景切换或背包重建后再刷新，避免每帧分配。
- 连续按 E 的安全性由交互物保证（拾取后 `IsActive=false`，重复调用返回拒绝原因），交互入口不需要自己加冷却。
- 同一帧命中多个交互物时取距离最近的一个；距离用 `Vector2.Distance(player.position, interactable.Anchor.position)`。

## 6. 背包与线索（`Inventory`）

挂载在玩家 Prefab 上，`InteractionContext.For` 会自动找到。

| API | 说明 |
|---|---|
| `bool TryAdd(ItemData item, out string reason)` | 入包；主线道具重复获取返回 `false` 并给原因 |
| `bool TryConsume(string itemId, int amount = 1)` | 消耗/移除；数量不足不改动背包 |
| `int Count(string itemId)` / `bool Has(string itemId)` | 按 `ItemData.ItemId` 查询 |
| `bool AddClue(ItemData clue, out string reason)` | 记入线索页；同一线索只记一次 |
| `IReadOnlyList<ItemData> Items` / `Clues` | 背包页 / 线索页数据 |
| 事件 `ItemAdded` / `ItemRemoved` / `ClueAdded` | UI 只订阅这些事件，不轮询内部列表 |

`ItemData` 是 ScriptableObject 配置（`Assets/Data/Items`），关键字段：`ItemId`（唯一键）、`DisplayName`、`Description`、`Category`、`Stackable`、`PickupFlag`、`InspectFlag`。**所有引用同一物品的地方必须填同一个 `ItemId`。**

## 7. 任务进度契约（`IQuestLog` / `PuzzleFlag`）

成员6 的 `QuestManager` 请实现同一接口（或持有 `QuestLogProvider`），谜题侧只依赖接口：

```csharp
public interface IQuestLog
{
    event Action<PuzzleFlag> FlagRaised;             // 首次写入时触发
    IReadOnlyCollection<PuzzleFlag> RaisedFlags { get; }
    bool HasFlag(PuzzleFlag flag);                    // None 一律视为满足
    bool SetFlag(PuzzleFlag flag);                    // 首次写入返回 true
}
```

当前 `PuzzleFlag` 取值（`Assets/Scripts/Quest/PuzzleFlag.cs`）：

`FlashlightAcquired`、`DutyNoteRead`、`FuseAcquired`、`PowerRestored`、`StairKeyAcquired`、`StairDoorUnlocked`、`ExitUnlocked`、`EvacuationComplete`、`BulletinRead`、`FirstHiding`、`None`。

对接约定：

1. **不要在两处各写一份判定**。谜题条件只读 `IQuestLog`；成员6 的 `QuestFlag` 如需独立枚举，在 `QuestManager` 内做映射并在周会记录里登记。
2. **标记是永久进度**：检查点重试不回滚（策划案 5.6）；临时状态（鬼怪、消耗品、躲藏占用）由成员6 重置，躲藏点调用 `HidingSpot.ForceRelease()`。
3. UI 只订阅 `FlagRaised`，不在按钮回调里改主线标记。

## 8. 躲藏点契约（`IHidableActor`）

躲藏点 `HidingSpot` 负责占用判定与提示，移动锁定与位移由玩家的 `IHidableActor` 实现：

```csharp
public interface IHidableActor
{
    bool IsHidden { get; }                 // 当前是否躲着
    bool IsCatchLocked { get; }            // 抓捕已成立/贴身锁定，成员2 写入
    void EnterHiding(HidingSpot spot);     // 锁移动、移到 spot.HidePoint、切躲藏表现
    void ExitHiding();                     // 恢复移动与表现
}
```

- 成员1：在玩家根节点实现 `IHidableActor`，`EnterHiding` 里冻结水平移动并把角色移到 `spot.HidePoint`。
- 成员2：追逐态且有效接触时把 `IsCatchLocked` 置 `true`；这样玩家在被抓瞬间按 E 不会躲进柜子获得免疫（T06）。
- 成员6：检查点重试/场景卸载时调 `HidingSpot.ForceRelease()`，避免残留占用。
- 躲藏**不保证绝对安全**：鬼怪是否发现由成员2 的感知决定，躲藏点只拒绝「抓捕已成立」时的进入。

## 9. 谜题机关（`PuzzleGate` 子类）

所有机关都是 `IInteractable`，完成后写一个 `PuzzleFlag` 并触发 `UnityEvent onSolved`（给成员3/5 接开门动画、灯光、音效）。条件未满足时 `GetPrompt` 返回具体原因。

| 机关 | 脚本 | 前置条件 | 完成反馈 | 写入标记 | 对应用例 |
|---|---|---|---|---|---|
| 配电箱 | `FuseBoxPuzzle` | 背包有 `item.fuse` | 「你把保险丝装进配电箱，走廊的灯重新亮了起来。」 | `PowerRestored` | T07 |
| 楼梯门禁 | `StairDoorPuzzle` | `PowerRestored` + 背包有 `item.stair_key` | 「钥匙插进锁孔，指示灯变绿，楼梯门滑开了。」 | `StairDoorUnlocked` | T08 |
| 出口联动装置 | `ExitSwitchPuzzle` | `PowerRestored` + `StairDoorUnlocked` | 「……出口锁扣弹开了。」 | `ExitUnlocked` | T11 |
| 出口安全区 | `EvacuationZone` | 进入触发区 + `ExitUnlocked` | 「225 全员撤出宿舍楼。」 | `EvacuationComplete` | T11 |

实测期望提示（自动化用例逐条断言，见 [谜题用例表.md](谜题用例表.md)）：

- 空手配电箱：`配电箱缺少「保险丝」：先去设备间把它找出来。`
- 门禁没电：`门禁没有电：先去配电箱恢复供电。`
- 门禁没钥匙：`门禁无响应：需要「门禁钥匙」。`
- 出口未开：`出口还锁着：先去门厅启动出口联动装置。`

## 10. 出口安全区（`EvacuationZone`）

- 物体需要 `Collider2D`（自动要求 Trigger）；玩家 Prefab 必须打 `Player` 标签，否则不会触发。
- 未达成 `ExitUnlocked` 时进入只发 `Feedback` 文本，不给通关；达成后写 `EvacuationComplete` 并触发 `onEvacuated`（成员5/6 接结局界面）。
- 重复进入不会重复结算；`TryEvacuate()` 同时供触发器和测试调用。

## 11. 异常与边界约定

| 情况 | 约定行为 |
|---|---|
| 连续按 E | 拾取物第二次返回拒绝文本，数量不变；谜题已完成时返回「已经处理好了」 |
| 缺少 `ItemData` / 线索数据 | `Debug.LogError` 带对象名，返回「物品数据缺失 / 线索数据缺失」，不抛异常 |
| 玩家没有 `Inventory` | 拾取/谜题返回「背包未初始化」，不空引用崩溃 |
| 场景没有 `IQuestLog` | `QuestLogLocator` 退回临时日志并只警告一次；标记仍可写入，方便单场景调试 |
| 已完成后重复操作 | 返回 `completedMessage`，不再写标记、不再播 `onSolved` |
| 重复拾取同一道具 | 背包去重（非堆叠），第二次返回「背包中已经有「X」了」 |
| 抓捕瞬间按 E 躲藏 | `Unavailable` + 「被鬼怪抓住的瞬间无法躲藏」 |
| 躲藏点被占用 | 第二人看到「储物柜里已经有人了」，无法进入 |
| 事件重复订阅 | 交互物不主动订阅 UI；`Inventory` 与 `IQuestLog` 的事件由订阅方负责退订 |
