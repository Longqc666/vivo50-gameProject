## 项目概述

《225：熄灯后》是一款以大学宿舍楼为舞台的2D横版单人恐怖逃生解谜游戏。某个深夜，宿舍楼突然停电，走廊传来异常脚步和求救声，整栋楼陷入诡异封锁。225宿舍六名成员全部幸存并保持联系。玩家控制其中一位成员，从225房间出发，搜集线索与关键道具，利用躲藏、观察巡逻规律和操作机关避开鬼怪，最终打通楼梯间及一楼出口，让所有室友成功撤离。

游戏采用类似横版格斗游戏的侧向镜头，但玩法重心不是拳脚战斗，而是“探索—获取信息—规划路线—规避危险—解锁通路”。独特体验来自熟悉的校园生活空间逐步异化，以及六名普通学生在恐惧中彼此协作、共同求生的故事。

## 体验定位

面向喜欢校园悬疑、轻度心理恐怖与叙事解谜的PC玩家。建议单次完整体验时长为15—25分钟，节奏先松后紧：225宿舍中的低压教学、二楼走廊的潜行探索、楼梯与门厅的集中追逐和逃脱。以光影、声音和环境变化塑造压迫感，控制突发惊吓频率，不依靠高难度战斗或复杂数值系统。

本策划案采用“最低可交付版本（MVP）优先”的原则：主线只覆盖三段可连续游玩的区域、一个主要鬼怪行为系统、一组相互关联的解谜任务和一个明确结局。六人分工为预计投入相近的协作计划，最终个人贡献仍以实际Git记录、资源文件和测试证据核验。

## 一 项目立项与团队分工

### 1 项目目标与制作范围

项目目标是完成一款Windows上可独立启动、可从主菜单进入并通关的2D校园恐怖游戏。基础版本须包含角色横向移动、交互与道具收集、鬼怪巡逻与追逐、躲藏或脱离追击、任务提示、三段连续场景、暂停与失败重试、最终逃脱结算，以及必要音画反馈。

必须完成：225房间、二楼走廊（含设备间或关键交互点）、楼梯与一楼出口；玩家控制一位主角，其他五位室友通过对话、立绘或节点事件参与叙事；至少一条能讲清原因与结果的主线谜题链。争取完成：动态灯光变化、分支对话、可选收集日志、额外鬼怪事件与更精细演出。明确不做：开放世界、六人实时联机、六角色实时跟随AI、多结局大分支、复杂战斗和大型3D建筑。

### 4 协作与版本管理

使用Git作为主版本管理工具，约定main分支保留可运行版本，功能在feature/player、feature/enemy、feature/level、feature/puzzle、feature/ui、feature/integration等分支开发，合并前由不同成员检查改动。Unity工程提交Assets、Packages和ProjectSettings，忽略Library、Temp、Logs和本地构建缓存；Prefab及场景编辑权以任务为单位协调，减少同一Scene的合并冲突。

代码和资源采用统一命名：D225_场景/Prefab名称、脚本按功能命名。每次提交说明“修改对象—完成内容—验证方式”；每个里程碑至少保留一份可运行版本与演示录屏。最终README注明Unity准确版本、启动场景、操作键位、构建步骤和已知问题。

### 5 主要风险与处理方案

| 风险 | 优先处理与降级方案 | 核查重点 |
|---|---|---|
| 范围过大 | 锁定三段区域和单一主线；先取消额外支线、复杂结局与多怪物种类。 | MVP流程仍然从开始到通关闭合。 |
| AI行为不稳定 | 先使用定点巡逻、距离+遮挡感知和状态机；路径复杂则收缩地图并用固定路点。 | 敌人可发现、追逐、丢失目标并返回巡逻。 |
| 场景或Prefab冲突 | 分区制作、明确文件责任人，合并前保存备份并进行Play Mode检查。 | 场景引用、碰撞体和触发器无丢失。 |
| 素材风格不一致 | 先用自制色块或可授权占位素材，统一调色与像素比例，后期替换。 | 无缺失资源，表现风格基本一致。 |
| 谜题卡关 | 关键线索不少于两处提示，重要交互出现明显图标，增加任务日志。 | 首次试玩者可以理解下一步目的。 |
| 构建与提交失败 | 提前执行Windows构建，所有外部包入库和锁定版本，预留一周整合。 | 在另一台Windows设备上能启动并操作。 |

### 6 策划协作与资源使用

优先采用小组原创关卡、文字、美术加工和程序。借用的图标、字体、音频或AI生成素材须记录来源、许可、修改人员和使用范围；不直接使用商业游戏的角色或音乐。AI可用于讨论逻辑、辅助排错和初稿，但关键代码需成员理解、修改、编译并实测，按课程要求另行填写AI使用核验记录。

## 二 详细游戏策划

### 1 游戏概念与核心体验

故事发生在普通大学宿舍楼。晚上熄灯后，全楼供电异常，电话与广播传出无法解释的提示，走廊的脚步声既熟悉又不合常理。225宿舍的六名成员均未遇害，他们通过纸条、宿舍电话或简短对话分工寻找出口。玩家主要操作一名室友进行危险区域探索，其余成员负责提示、线索解读与结尾集合，不采用五名NPC同时跟随的高成本实现。

叙事主题为“在恐惧中互相信任”，玩法以判断风险与逐步解锁通道为核心。与《拳皇》式侧视镜头相同之处在于场景横向展开；不同之处在于不采用格斗连招和对战回合。游戏不会奖励主动击杀鬼怪，而是通过灯光、足音和遮挡提供可理解的潜行选择。

### 2 核心玩法循环

| 环节 | 玩家行为 | 系统反馈 / 下一目标 |
|---|---|---|
| 观察目标 | 查看任务栏、背景提示、被锁住的门与鬼怪位置。 | 标注可调查对象和当前主线目标。 |
| 探索移动 | 左右移动，在安全位置靠近物品与线索。 | 镜头跟随，交互图标亮起；奔跑增加暴露风险。 |
| 调查解谜 | 阅读便笺、拾取物品、使用钥匙或修复配电。 | 背包更新，门禁状态或照明发生改变。 |
| 规避威胁 | 观察巡逻路线、利用柜子躲藏、等待追逐结束。 | 敌人从巡逻转为搜寻或追逐，音画强度变化。 |
| 推进检查点 | 解锁新区域，触发室友联络事件。 | 保存关键进度并更新任务文本。 |
| 逃脱或重试 | 打开楼外出口并进入结算；被抓住则重试。 | 触发通关剧情；失败返回最近检查点。 |

### 3 玩家目标、成功与失败

短期目标：在225宿舍找到手电筒和第一张线索纸条，学会移动与互动。中期目标：进入走廊找出配电室、修复局部电力、取得通往楼梯的钥匙（或门禁授权）。最终目标：通过楼梯与门厅机关，打开出口，触发六名室友共同撤离的结局。

成功条件由任务状态控制：获得楼梯通行条件、恢复必要的门厅机关供电、到达楼外安全触发区且完成结尾事件。失败条件：主角在未进入躲藏状态下被鬼怪有效接触并完成抓捕判定。失败后可“从最近检查点重试”或“返回主菜单”；检查点重置鬼怪位置，保留已确认的关键任务进度，避免重复收集产生死锁。

### 4 操作与镜头

| 输入 | 角色动作或系统操作 | 反馈与限制 |
|---|---|---|
| A / D 或 ← / → | 左右移动，基础移动速度按参数表。 | Animator切换待机/行走，水平镜头跟随。 |
| 左Shift（按住） | 短暂奔跑，消耗耐力并增大脚步噪声。 | 耐力条下降，环境音突出急促脚步。 |
| E | 在交互范围内调查、拾取、开门、藏入/离开柜子。 | 显示对象名称；不可操作时显示原因。 |
| Tab | 打开/关闭背包及线索页。 | 游戏暂停或降低行为节奏（以最终实现为准）。 |
| F | 切换手电筒（获得手电后可用）。 | 改变照明范围并播放开关音。 |
| Esc | 暂停、恢复、返回设置或主菜单。 | 暂停时冻结游戏状态和敌人行为。 |

镜头采用固定侧视的2D横版表现，主角仅沿水平平面路线推进，竖向平台跳跃不是核心机制；场景纵深由多层背景与室内遮挡营造。相机跟随采用平滑偏移及边界锁定，避免墙外留白。不同区域间通过门、黑场或淡入淡出衔接，优先保证视觉稳定与操作可读性。

### 5 场地与系统规则

#### 5.1 场景空间与物理边界

基础交互以2D碰撞体和Trigger为主。每个区域设置地面、墙体和可交互物；场景边界阻止玩家走出有效范围。物品仅在玩家与交互对象距离不大于约1.2 Unity单位且存在有效交互状态时可操作。玩家与障碍的碰撞使用Rigidbody2D及Collider2D处理；鬼怪视线可用Physics2D.Raycast进行墙体遮挡判断。

#### 5.2 探索、移动与提示

新玩家从225寝室的安全环境进入。剧情文本提示“断电后先找照明”，玩家拾取手电、尝试房门后出现第一个任务标记。交互物区分“可拾取、可调查、可使用、暂不可用”四种状态；任务提示优先显示当前目标而非提前透露所有解法。所有必需物品可在明确范围找到，不设置随机刷新。

#### 5.3 鬼怪状态机与感知

基础鬼怪包含四个状态：Patrol（沿路点巡逻）、Investigate（前往声源或最后目击位置）、Chase（追逐可见玩家）、Return（放弃追逐后返回巡逻）。玩家进入鬼怪前方视野且没有遮挡，持续满足识别时间阈值则触发追逐；奔跑产生更大范围的噪声，可能使敌人前往声源调查。鬼怪丢失视线后先在最后目击点短暂搜索，而不是瞬间传送或永远追踪。

为控制实现难度，首个可交付版本只使用一类巡逻鬼怪、二维距离判断与有限巡逻点，不实现动态导航网格或多敌人群体协同。捕捉判定需满足敌人处于追逐/有效碰撞状态、玩家不在安全躲藏标记内，防止穿墙触发失败。

#### 5.4 躲藏与失败重试

走廊的储物柜、清洁间等可指定为躲藏点。玩家接近后按E进入，角色临时隐藏并锁定移动；若鬼怪未直接看见进入过程，脱离警戒后可安全离开。躲藏点不保证“任何时刻绝对安全”：在敌人已贴身抓捕时禁止瞬间免疫。若玩家被抓，播放短暂失败动画后显示“重试检查点”，不在课程原型阶段增加永久死亡惩罚。

#### 5.5 道具与主线谜题链

| 步骤 | 所需信息 / 道具 | 规则与反馈 | 解锁结果 |
|---|---|---|---|
| 宿舍准备 | 手电筒、宿舍便笺 | 调查桌面获得照明和配电室位置线索。 | 允许探索黑暗走廊。 |
| 恢复供电 | 保险丝 / 配电箱 | 在设备间找到保险丝，返回配电箱安装。 | 局部灯光恢复；部分门禁变为可操作。 |
| 开启楼梯门 | 门禁钥匙或密码线索 | 观察公告栏与值班台，结合纸条解开单一锁具。 | 二楼楼梯间开放。 |
| 穿越门厅 | 主电闸或出口按钮 | 在鬼怪巡逻间隙激活出口联动装置。 | 出口从锁定切换为开启。 |
| 完成撤离 | 集结事件完成标志 | 到达出口触发225室友集合与结束动画。 | 显示通关结算页面。 |

谜题原则：每一个障碍均有可观察的原因和线索来源。例如配电箱提示“缺少保险丝”，物品检视说明用途；门禁密码线索需出现在同区域可调查材料中，密码不强制设成固定的玩家事先不知道的数字。若解谜进度中断，任务面板记录已获得线索，避免玩家因记忆负担卡住。

#### 5.6 关卡检查点与任务状态

每一主要区域末端布置检查点，存储Scene ID、玩家生成点、关键物品集合和QuestFlag。加载检查点时重置当前区域鬼怪、消耗品与视觉特效；已经完成的永久性任务（例如电路修复）不应恢复为未完成，也不能使钥匙在已开门后丢失。切换场景前写入内存进度；正式磁盘存档属于“争取完成”，不是MVP必须项。

### 6 角色、敌人、道具与环境

| 对象 | 定位 / 属性 | 与玩家的交互 | 表现需求 |
|---|---|---|---|
| 玩家主角 | 225宿舍六人之一，可左右移动、奔跑、调查、躲藏。 | 键盘输入；受鬼怪追捕及检查点规则约束。 | 待机、行走、奔跑、受惊等基础动画。 |
| 其他五位室友 | 全部存活，主要通过对话和关键节点共同推进逃生。 | 提供信息或参与结尾演出，不实时跟随寻路。 | 立绘、对话框、少量场景定位。 |
| 巡逻鬼怪 | 单类敌人，Patrol/Investigate/Chase/Return。 | 对视线、脚步声和玩家躲藏作出响应。 | 剪影、脚步、警戒与追逐提示。 |
| 手电筒 | 可切换的环境照明辅助。 | 拾取后F键开关。 | 锥形光或2D灯光、开关音。 |
| 保险丝/钥匙 | 不可重复使用的主线进度物品。 | 拾取进入背包，满足机关条件时使用。 | 物品图标、获得提示、任务变化。 |
| 配电箱/门禁/出口 | 条件触发机关。 | E交互，根据任务状态显示反馈。 | 设备音效、灯光、门状态变化。 |

### 7 关卡设计与推进流程

主线路径按教学与压力逐渐提升：225房间（低风险）→ 二楼走廊及设备间（首次威胁）→ 楼梯与一楼门厅（高压脱离）→ 楼外出口（结尾）。各区域之间明确设置回路和关键目标，避免过度复杂的多楼层迷宫。

| 区域 | 核心目标 | 挑战与节奏 | 完成条件 / 证据 |
|---|---|---|---|
| 区域A 225宿舍 | 拿到手电筒、阅读线索、与室友确认外出计划。 | 安全教学、气氛铺垫，强调可调查物。 | 玩家可操作并成功触发走廊门。 |
| 区域B 二楼走廊 | 躲避巡逻鬼怪、收集保险丝、修复配电箱。 | 第一次巡逻观察，提供可见躲藏点。 | 配电恢复、任务更新、楼梯入口可进入。 |
| 区域C 楼梯及门厅 | 依据门禁线索进入门厅并解除出口锁定。 | 照明变差、鬼怪追逐，设置检查点。 | 出口开启动画与完整逃脱触发。 |
| 结尾 逃生出口 | 六名225成员成功汇合。 | 气氛由紧张转为释然。 | 出现通关页、返回主菜单入口。 |

| 界面 | 显示信息 | 玩家操作与系统反馈 |
|---|---|---|

### 9 数值参数与难度调校

下表为原型建议值，用于保证规则可讨论、可测试；并非已经跑通的最终数据。单位按Unity世界单位与秒记，须结合碰撞体尺寸及实际试玩更新。

| 参数 | 原型起始值 | 设计依据 / 调整规则 |
|---|---|---|
| 玩家步行速度 | 3.0 单位/秒 | 可准确接近交互点，避免长走廊移动过慢。 |
| 玩家奔跑速度 | 4.7 单位/秒 | 明显快于步行，但持续使用暴露风险更高。 |
| 耐力容量 / 消耗 | 100点；奔跑15点/秒 | 约6.7秒连续奔跑，限制全程冲刺。 |
| 耐力恢复 | 停跑后1.5秒开始；18点/秒 | 允许局部逃脱而不鼓励不停奔跑。 |
| 物品交互半径 | 1.2 单位 | 玩家可直观看到可操作目标。 |
| 鬼怪巡逻速度 | 2.1 单位/秒 | 玩家步行可在观察后绕过。 |
| 鬼怪追逐速度 | 4.1 单位/秒 | 高于步行、低于短暂奔跑，形成逃脱窗口。 |
| 视线发现范围 | 前向约4.5单位，有遮挡判定 | 必须配合朝向与墙体遮挡，不能隔墙发现。 |
| 奔跑声音半径 | 约5.0 单位；步行约2.0 | 用声音制造路线选择，不做复杂声传播。 |
| 丢失视线搜索时长 | 约3秒 | 给躲藏成功提供清晰反馈与等待时间。 |
| 检查点 | 每个主要区域出口附近至少1个 | 失败后重复路程控制在合理范围。 |

难度曲线：A区无主动威胁；B区先展示固定巡逻路线，再引入一次视线规避；C区缩短安全间隔并强化追逐，但仍保留清晰躲藏点。测试时优先调整路点分布和敌人感知时间，其次调整玩家速度，避免单纯提高鬼怪数值造成挫败。

### 10 美术、音效与恐怖氛围

整体采用2D横版偏写实或低饱和手绘风格，以冷蓝灰作为公共区域主色，宿舍桌灯和应急灯保留少量暖色光。人物按统一比例制作正侧面或简化动画，物品与可交互区域用轮廓光或提示符号区别于纯装饰。背景采用三层视差或静态层叠即可，不追求大量3D模型。

| 音画类别 | 触发场景 / 目标效果 | 规则与注意事项 |
|---|---|---|
| 背景环境声 | 宿舍风扇、电流噪声、远处脚步、门轴响。 | 环境声分区变化，避免持续过响。 |
| 追逐音效 | 敌人由调查切换至追逐，心跳或低频增强。 | 追逐解除逐渐淡出，避免重复叠加。 |
| 交互音效 | 拾取、开关手电、开门、安装保险丝与按钮。 | 有效操作一次播放一次，音效与动作对应。 |
| 灯光变化 | 停电、恢复配电、门厅警报。 | 警示兼有文字/图标，避免纯闪烁刺激。 |
| 人物动画 | 行走、奔跑、藏入柜子、被发现、结尾汇合。 | 优先保证反馈明确，使用有限动画帧。 |

恐怖表现遵循“可感知原因的紧张”：先给声响或影子，再出现威胁；重要信息不得被暗场遮蔽。闪屏、音量骤增等效果应尽量克制，必要时提供低惊吓或特效强度选项作为扩展。

### 11 游戏状态与异常处理

| 状态 | 进入条件 | 允许行为与退出条件 |
|---|---|---|
| 初始化 | 启动Windows程序。 | 检查必要场景与配置；进入主菜单，失败显示错误提示。 |
| 主菜单 | 初始化完成或返回菜单。 | 开始、设置、退出；开始建立本局状态。 |
| 探索 | 进入可玩场景。 | 移动、交互、拾取、任务推进；被抓则失败，通关则结局。 |
| 躲藏 / 追逐 | 玩家进入躲藏区或鬼怪发现主角。 | 更新敌人状态、声音和HUD；满足解除条件返回探索。 |
| 暂停 | 玩家按Esc。 | 冻结角色与AI状态；继续、重试或返回。 |
| 失败 / 检查点 | 有效抓捕判定成立。 | 重置敌人及区域临时状态，保留已完成关键任务。 |
| 通关结算 | 出口事件完成且任务条件齐备。 | 显示六人撤离结局；可返回主菜单。 |

异常处理重点包括：连续按E不得重复拾取同一物品；关门或切换场景期间不应再次触发门事件；进入暂停后敌人不能继续抓捕；玩家在关卡加载完成前不能提前接受键盘输入；丢失引用时应在Unity控制台记录定位信息，而不是直接造成无法继续的黑屏。

| 模块 | 主要职责 | 推荐实现方式（规划） |

以课程指南中的Unity 2023.2.20作为暂定环境，团队建工程时以实际版本号为准并锁定Package依赖。Windows构建默认键鼠输入，避免引入微信SDK、云函数、在线账号或付费服务；确需外部插件时应说明安装和授权。
