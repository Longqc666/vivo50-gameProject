## 1. 一句话

流程模块只做四件事：**决定现在是什么状态、决定能不能被打断、记住玩家走到哪、把三段场景串起来**。
角色怎么动、鬼怪怎么追、界面怎么画都不在这里；其他模块通过下面 5 个东西接入即可，不需要改流程代码。

| 接入点 | 谁用 | 一句话 |
|---|---|---|
| `GameState`（枚举 + 静态门面） | 全员 | 读当前状态、判断能不能操作 |
| `GameManager`（单例） | 成员2/3/5 | 报抓捕、请求切区、存档检查点 |
| `IQuestLog` + `PuzzleFlag` | 成员4 | 任务进度的唯一来源（本模块只包装，不另立判定） |
| `IGameFlowView` | 成员5 | 界面适配器需要实现的 7 个方法 |
| `Time.timeScale` 归属 | 全员 | 只有 `GameManager` 写它 |

## 2. 状态 `GameState`

```csharp
public enum GameStateId { Init, MainMenu, Explore, Paused, Failed, Ending }

// 用法与文档一致：
if (GameState.Current != GameState.Explore) return;
```

| 状态 | 含义 | 允许的操作 |
|---|---|---|
| `Init` | 流程未接管（编辑器里单独打开关卡场景） | 不冻结任何东西，方便分区调试 |
| `MainMenu` | 主菜单 | 不能操作角色 |
| `Explore` | 探索中 | **唯一**允许移动/交互/被抓捕结算的状态 |
| `Paused` | 暂停 | 冻结角色与鬼怪，**不结算抓捕** |
| `Failed` | 已被抓，等待重试 | 只能重试或返回主菜单 |
| `Ending` | 撤离成功 | 只能返回主菜单 |

状态迁移表（`GameStateMachine`，非法迁移会被拒绝并在控制台写原因）：

```
Init     → MainMenu / Explore
MainMenu → Explore
Explore  → Paused / Failed / Ending
Paused   → Explore / MainMenu        ← 暂停期间不能转 Failed
Failed   → Explore / MainMenu
Ending   → MainMenu
```

`GameState.BlocksGameplayInput` 在 `MainMenu / Paused / Failed / Ending` 为真；
`Init` 故意为假——否则在编辑器里直接打开 `Scene_A_Dorm` 按 Play 会连路都走不了。

## 3. `GameManager`（单例）

只有**主菜单场景 `Scene_Boot`** 会自动创建它（`GameBootstrap`），之后 `DontDestroyOnLoad` 跨场景存活。
在 A/B/C 等关卡场景里直接按 Play 时它**不存在**，所以不会改变成员1/3/5 原有的单场景调试行为。

| 成员 | 签名 | 说明 |
|---|---|---|
| 属性 | `GameManager.Instance` | 没接管流程时为 `null`，调用前先判空 |
| 属性 | `State` / `Quest` / `Checkpoints` / `CurrentRegion` / `CurrentCheckpoint` / `IsBusy` | 只读 |
| 事件 | `StateChanged(旧, 新)` | HUD/音效可订阅 |
| 事件 | `CheckpointSaved(CheckpointData)` | 存档点提示 |
| 方法 | `bool BeginGame()` | 主菜单「开始游戏」：清空进度并从 A 区入口开始 |
| 方法 | `bool RequestPause(bool paused)` | 只有 `Explore↔Paused` 合法，其余返回 false |
| 方法 | `bool NotifyPlayerCaught(string source)` | **成员2 抓捕判定成立时调用** |
| 方法 | `bool RetryFromCheckpoint()` | 失败页「从检查点重试」 |
| 方法 | `bool ReturnToMainMenu()` | 暂停/失败页「返回主菜单」 |
| 方法 | `bool NotifyEvacuated()` | 撤离结算（写 `EvacuationComplete` 时自动触发） |
| 方法 | `bool SaveCheckpointNow(string spawnId)` | 手动存档；`spawnId` 为空时取已通过的最右检查点 |

调用约定：

```csharp
// 成员2（EnemyAI）：抓捕判定成立（追逐态 + 有效接触 + 玩家未躲藏）时
GameManager.Instance?.NotifyPlayerCaught("EnemyAI");

// 成员3（触发区）：想手动切区时
gameManager.RequestRegionTransition("B", "CP_B_Entry");   // 见第 6 节
```

`NotifyPlayerCaught` 在以下情况**不会**结算（对应异常清单）：
当前不是 `Explore`（比如暂停中）、正在切场景/重试（`IsBusy`）、已经结算过。

## 4. `Time.timeScale` 归属（重要）

流程模块是**唯一**写 `Time.timeScale` 的组件：

- 探索 = `1`；
- 暂停 / 失败 / 结算 / 切场景淡出与加载 = `0`。

因此：

1. 成员5 的 `UiRouter.manageTimeScale` 必须为 **false**（本模块生成的 `D225_FlowMenu.prefab` 已设好）。
2. 成员1 的移动、耐力、交互提示都按 `Time.deltaTime` / `Time.timeScale` 工作，**不需要改脚本**就能被冻结。
3. 鬼怪 AI 只要按 `Time.deltaTime` 走（或 `FixedUpdate` 里用速度），暂停时自然停手；若 AI 用 `unscaledDeltaTime` 做状态计时，需要自己在 `Update` 开头判断：

```csharp
if (!GameState.IsGameplayActive) return;   // 暂停/失败/加载时不推进 AI
```

## 5. 任务状态 `QuestJournal`

`QuestJournal` 实现成员4 的 `IQuestLog`，只是把场景里的 `QuestLogProvider`（找不到时为临时日志）包装起来：

- 谜题侧照旧读写 `IQuestLog`，**不需要**知道流程模块存在；
- `Restore(snapshot)` 只补写不清空，符合「标记是永久进度」；
- `Clear()` 用于新开一局，只对 `QuestLog` 生效，不会误清别人的实现；
- `EvacuationComplete` 写入时自动进入 `Ending`（`GameManager` 订阅 `FlagRaised`）。

> 每人每场景一个 `QuestLogProvider` 时，切场景后流程会在新场景重新解析来源，并把检查点里的标记写回去。

## 6. 场景衔接与区域出口

区域表在 `RegionCatalog`（纯代码，不依赖场景内容）：

| 区域 | 场景 | 入口出生点 | 出口条件 | 下一区 |
|---|---|---|---|---|
| A | `Scene_A_Dorm` | `CP_A_Spawn` | 走到 `x ≥ 8.4` | B |
| B | `Scene_B_Corridor` | `CP_B_Entry` | 走到 `x ≥ 28.3` **且** `StairDoorUnlocked` | C |
| C | `Scene_C_Hall` | `CP_C_Entry` | 无（靠 `EvacuationZone` 写 `EvacuationComplete` 结算） | — |

坐标取自成员3 的关卡数据（`D225LevelLayoutData.g.cs`：`Door_ToCorridor` 在 x=9、楼梯门在 x≈28.1）。

设计意图：**出口判定不往成员3 的场景里加组件**，因此

- 关卡重新生成后不需要再手工挂一次触发器；
- 出口条件（B 区必须先开楼梯门）可以写成 EditMode 用例直接断言；
- 切场景流程：淡出 → `LoadSceneAsync` → 找 `CP_*` 出生点 → 摆角色 → 恢复背包/标记 → 重置临时状态 → 淡入 → `Explore`。

`CP_*` 命名约定：**名字即出生点 ID**（与成员3 的 `Checkpoints` 组一致），检查点按 X 从左到右排序、只前进不回退。

### 6.1 构建后冒烟（回归用）

打包后的程序带一个开关，跑完「主菜单 → A → 暂停/恢复 → B → 门禁拦截 → C → 结算 → 主菜单」并把结果写进日志与退出码：

```powershell
Build/Windows/D225.exe -d225-smoke -logFile Build/smoke.log
```

不带该开关时 `FlowSmokeDriver` 不会被创建，对正常游玩与编辑器零影响。适合每次构建后跑一遍（T09/T10/T11/T12）。

## 7. 检查点与失败重试（T09）

`CheckpointData` 保存：`SceneId`、`SpawnId`、关键道具与线索（内存引用）、`PuzzleFlag` 快照。

- 进入区域、通过 `CP_*`、被抓的瞬间各存一次；
- **重试 = 重载检查点所在场景**（策划案 5.6）：鬼怪位置、消耗品、隐藏状态全部重置；
- 永久进度保留：道具/线索从检查点写回背包，`PuzzleFlag` 写回任务日志；
- 临时状态重置：所有 `HidingSpot.ForceRelease()`，并对玩家 `SendMessage("ResetAfterFailure")`
  ——所以成员1 的 `PlayerHiding.ResetAfterFailure()` 不需要改签名，也不用和流程模块互相引用。

## 8. `IGameFlowView`（成员5 接界面用）

流程模块不引用任何界面类型，只认这个接口；本仓库已提供实现
`D225.Flow.UiRouterFlowAdapter`，包装成员5 的 `UiRouter`：

| 方法 | 何时调用 |
|---|---|
| `ShowMainMenu()` | 进入主菜单 |
| `ShowGameplay()` | 开始/重试完成，显示 HUD |
| `ShowPause(bool)` | 暂停开/关 |
| `ShowFail()` | 抓捕结算 |
| `ShowEnding()` | 撤离结算 |
| `FadeOut/In(seconds)` | 切场景前后（用 `unscaledDeltaTime`，timeScale=0 也能播） |
| `SetFadeInstant(alpha)` | 加载中直接拉黑 |

界面上的按钮通过 `UiRouter` 的已有事件接入，**不需要改 UiRouter**：

```csharp
router.PausedChanged        += paused  => gameManager.RequestPause(paused);
router.RetryRequested       += ()      => gameManager.RetryFromCheckpoint();
router.ReturnToMenuRequested += ()     => gameManager.ReturnToMainMenu();
```

另外，主菜单的「开始」按钮原来只调 `UiRouter.StartGame()`（只切页面、不加载场景）。
适配器会在运行时给名为 `Start` 的按钮**追加**一个监听去调 `GameManager.BeginGame()`，
所以成员5 既有的按钮事件不用改，也不会被覆盖。

## 9. 与各模块的边界（避免重复实现）

| 成员 | 负责 | 不负责 |
|---|---|---|
| 成员1 | 移动/耐力/镜头/交互入口、`PlayerHiding` | 状态判定、存档、切场景 |

| 成员3 | 三段场景灰盒、碰撞、`CP_*` 空锚点 | 出口逻辑、出生点摆放（按名字约定即可） |

## 10. 已知缺口（截至 2026-11-22）

1. **局内 HUD 未接入正式场景**：成员5 的 `D225Hud` 要求拖拽赋值（同场景的 player/interactor/tracker/inventory），
   本模块只提供菜单/暂停/失败/结算页，不代做 HUD。接入方式见第 8 节与 [成员6-交付清单.md](成员6-交付清单.md) 第 6 节。
2. **鬼怪 AI 尚未提交**：`NotifyPlayerCaught` 与暂停冻结已就位，等成员2 的实现接入。
3. **C 区结算**：依赖成员4 的 `EvacuationZone` 写 `EvacuationComplete`；若该 Prefab 未摆进 C 区，结算不会触发。
4. **磁盘存档**：检查点只在内存里（策划案把磁盘存档列为「争取完成」），退出游戏即清空。
