# 《225：熄灯后》团队分工表

> 依据：[策划案.md](策划案.md)（V1.0 立项策划稿）。
> 团队 6 人，采用「模块主责 + 同伴复核」，计划工作量各约 1/6（≈16.7%）。
> 本表是计划分工，不是完成记录；个人贡献以 Git 提交、资源文件、测试与演示证据核验。

## 四、协作约定

**分支与提交**：`main` 只保留可运行版本；各人功能在自己的 `feature/*` 分支开发，合并前由另一名成员检查。提交说明统一「修改对象 — 完成内容 — 验证方式」，例如 `PlayerController — 加入耐力消耗 — T02 手测通过`。

**接口契约**（变更需在周会说明并同步本表）：

| 契约 | 定义方 | 使用方 | 内容 |
|---|---|---|---|
| `IInteractable` | 成员4 | 成员1、3 | 提示文本、可交互条件、执行结果 |
| 噪声事件 | 成员2 | 成员1 | 步行 2.0 / 奔跑 5.0 半径的声源上报 |
| `GameState` | 成员6 | 全员 | 初始化/菜单/探索/暂停/失败/结算 |
| `QuestFlag` 与事件 | 成员6 | 成员4、5 | 任务状态变更；UI 只订阅不判定 |
| 检查点数据 | 成员6 | 成员3 | SceneID、出生点、关键物品、QuestFlag |
| `EnemyAI` 状态 | 成员2 | 成员5、6 | 四态枚举，供 HUD 与音效订阅 |

**文件归属**：`Scripts/Player`、`Scripts/Enemy`、`Scenes`、`Scripts/Interact`、`Scripts/UI`、`Scripts/Core` 分别由成员 1/2/3/4/5/6 主责；同一 Scene 同一时间只允许一人编辑，改前在群里报备并先拉取。`Library`、`Temp`、`Logs`、本地构建缓存不入库。

**节奏**：每周一次联调 + 一次交叉试玩；每阶段结束保留一份可运行版本与录屏；关键代码由非作者阅读并复测。

**证据**：每人至少保留「代码提交 + 资源/场景 + 自测记录」三类证据；素材登记文件路径、作者/出处、授权、修改说明与关联提交；AI 辅助内容按课程要求另填核验记录。
