### 议题与结论

**议题 1：工程环境与骨架**

- 结论：Unity 版本锁定 **2022.3.62f3c1**（本机已安装，README 已同步）；包依赖 `com.unity.test-framework 1.1.33`、`com.unity.ugui 1.0.0`，其余为内置模块。
- 结论：仓库根目录直接作为 Unity 工程根（`Assets/`、`Packages/`、`ProjectSettings/` 入库；`Library/`、`Temp/`、`Logs/`、构建缓存不入库）。
- 结论：工程 Product Name 为 `D225`，Company 为 `vivo50`；启动场景由成员3 在 M1 阶段提交。

**议题 2：交互契约定稿（4-1）**

- 结论：`IInteractable` 采用六成员接口（名称/锚点/是否活跃/四态判定/提示/执行），距离与按键不在接口内。
- 结论：四态为「可拾取 / 可调查 / 可使用 / 暂不可用」，提示统一 `[E] 动词 名称`，不可用时必须给原因。
- 结论：躲藏点通过 `IHidableActor` 与玩家解耦；抓捕锁定由成员2 写入 `IsCatchLocked`。
- 结论：任务进度以 `IQuestLog` + `PuzzleFlag` 为最小契约，成员6 的 `QuestManager` 实现同一接口并做 `QuestFlag` 映射。
- 风险：以上接口在成员1/2/5/6 的实际实现中可能需要微调；变更必须走「周会提出 → 更新接口文档与分工表变更记录 → 通知使用方」。

**议题 3：里程碑与分工确认**

- 确认沿用 [分工表.md](分工表.md) 的 M1–M4 划分与 1/6 工作量目标。
- 强调：分工表是计划，个人贡献以 Git 提交、资源、测试证据核验（分工表开头的声明保留）。

**议题 4：分支与提交规范**

- `main` 只保留可运行版本；个人功能在 `feature/*` 开发。
- 提交说明统一「修改对象 — 完成内容 — 验证方式」，例如：`Interact — 加入四态交互与谜题链 — T07/T08/T11 自动化用例通过`。
- 合并前由另一名成员检查；负责人合并时在变更记录注明「待复核」。
