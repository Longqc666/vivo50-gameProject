## 2. 代码结构

```
Assets/Scripts/Core/                程序集 D225.Core（autoReferenced，其他脚本可直接 using D225.Core）
  GameState.cs                      六态枚举 + 静态门面（GameState.Current / BlocksGameplayInput）
  GameStateMachine.cs               迁移表（纯 C#，可单测）：暂停期间不允许失败
  QuestJournal.cs                   IQuestLog 包装：转发、快照、恢复、Clear
  CheckpointBook.cs                 CheckpointData + 检查点账本（只前进不回退）
  RegionCatalog.cs                  三段区域与出口规则（纯 C#，坐标取自关卡数据）
  GameManager.cs                    流程总控：状态、timeScale、切区、检查点、重试、结算
  GameBootstrap.cs                  只在 Scene_Boot 自动创建 GameManager
  IGameFlowView.cs                  界面适配接口（流程不引用 UI 程序集）
  FlowSmokeDriver.cs                构建后冒烟（仅 -d225-smoke 启动）：整条链真实跑一遍

Assets/Scripts/Flow/                界面适配层（Assembly-CSharp，可引用成员5 的 UiRouter）
  UiRouterFlowAdapter.cs            包装 UiRouter：订阅它的三个事件，实现 IGameFlowView + 转场黑幕

Assets/Editor/D225/Flow/            编辑器装配器（Assembly-CSharp-Editor）
  D225FlowSceneBuilder.cs           生成界面预制体 / 主菜单场景 / Build Settings / Windows 构建

Assets/Tests/Core/                 程序集 D225.Core.Tests（Editor only）
  EditMode/GameStateMachineTests.cs 12 条：合法/非法迁移、幂等、事件顺序
  EditMode/QuestJournalTests.cs     10 条：去重、快照排序、恢复不清空、Dispose
  EditMode/CheckpointTests.cs        9 条：抓取、背包恢复、永久进度、账本单调
  EditMode/RegionCatalogTests.cs    10 条：A 门、B 门条件、C 无出口、场景名映射

Assets/Prefabs/UI/D225_FlowMenu.prefab   流程界面（由成员5 的 UI 场景抽取 + 转场黑幕 + 结算页）
Assets/Scenes/Scene_Boot.unity           主菜单/启动场景（Build Settings 第 0 位）
```

设计上的三条硬约束：

1. **不改别人的脚本**：成员1 的移动/躲藏、成员2 的 AI、成员3 的场景、成员4 的交互、成员5 的 UiRouter 全部保持原样；
   对接只走接口（`IQuestLog`、`IGameFlowView`）、Unity 消息（`SendMessage("ResetAfterFailure")`）与序列化字段。
2. **不改别人的场景**：出口按坐标判定，检查点按 `CP_*` 名字收集，因此关卡重新生成后不用再挂组件。
3. **只有一处写 `Time.timeScale`**：`GameManager`；因此成员1 的脚本不改也能被暂停冻结。

## 4. 异常处理清单（6-5，对应策划案 9「状态与异常」）

| 异常 | 处理 | 落点 |
|---|---|---|
| 连续按 E 重复拾取 | 交互物自己拒绝（成员4）；流程层不重复结算 | 已有契约，新增用例 `RestoreInventory_IsIdempotent` |
| 切场景期间重复触发门 | 转场 `transition != null` 时直接忽略并记日志 | `GameManager.StartTransition` |
| 暂停期间仍被抓 | `Paused → Failed` 在迁移表里不合法，`NotifyPlayerCaught` 只在 `Explore` 生效 | `GameStateMachineTests.Paused_CannotFail...` |
| 关卡加载完成前输入 | 加载/淡出期间 `timeScale = 0`，成员1 的移动与交互入口按 timeScale 自动停手 | `GameManager.TransitionRoutine` |
| 丢失引用 | `CacheSceneActors` 找不到 Player、`PlacePlayer` 找不到出生点时 `Debug.LogWarning` 带对象名 | `GameManager` |
| 重复/非法状态请求 | `TryEnter` 返回 false 并写中文原因，重复请求按幂等处理 | `GameStateMachine.Rejected` |
| 检查点跨场景不丢进度 | 新场景的 `QuestLogProvider` 会被重新解析，标记从检查点写回 | `QuestJournal.ForCurrentScene` + `RestoreFromCheckpoint` |
